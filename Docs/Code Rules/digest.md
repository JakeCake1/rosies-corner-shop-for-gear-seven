# Code Rules Digest

Digest of the must-follow rules; the full files in `Docs/Code Rules/` are the source of truth. Open a full file for its topic or when a rule here is unclear.

## Stack

- Async: UniTask only; no coroutines, `async Task`, `Awaitable`. (tech-stack §General)
- DI: VContainer only; no static singletons, `FindObjectOfType`, Service Locator. (tech-stack §General)
- Observable state/events: UniRx (`ReactiveProperty`, `Subject`, `ReactiveCollection`); no R3. (tech-stack §General)
- Animation: DOTween; no `Animator` for UI. Assets: Addressables; never `Resources`. UI: UI Toolkit; no uGUI/TextMeshPro. (tech-stack §General)
- Avoid mutable static state (domain reload may be off); else reset in `[RuntimeInitializeOnLoadMethod(SubsystemRegistration)]`. (tech-stack §General)
- Services: `builder.Register<T>(Lifetime.Singleton).AsImplementedInterfaces()`; depend on interfaces. (tech-stack §VContainer / Registration)
- Startup/tick/async-init logic: `RegisterEntryPoint<T>()` + `IInitializable`/`IStartable`/`ITickable`/..., not a `MonoBehaviour`. (tech-stack §VContainer / Registration)
- `MonoBehaviour` deps: `[Inject] public void Construct(...)`, no field injection; plain classes: constructor injection only, no `[Inject]`. (tech-stack §VContainer / Registration)
- Configs: `RegisterInstance`; runtime-with-params creation: factory. `IObjectResolver` only in factories/scopes/bootstrap. (tech-stack §VContainer / Registration)
- Injectable prefabs: `resolver.Instantiate(prefab, parent)`, never `Object.Instantiate` or `Addressables.InstantiateAsync`. (tech-stack §VContainer / Instantiation)
- Scene-only services go in a scene `LifetimeScope` (child of project scope); temporary contexts use `CreateChild`. (tech-stack §VContainer / Scopes)
- Return `UniTask`/`UniTask<T>`; never `async void`; fire-and-forget = `UniTaskVoid` + `.Forget()`; never discard a task. (tech-stack §UniTask)
- Pass `CancellationToken` (last parameter) through every async method and inner await; `GetCancellationTokenOnDestroy()` or a CTS cancelled in `Dispose()`. (tech-stack §UniTask)
- Catch `OperationCanceledException` only at top level. Use `UniTask.Delay/Yield/WaitUntil`, not `Task.Delay`. (tech-stack §UniTask)
- Heavy/I/O work: `SwitchToThreadPool`, then `SwitchToMainThread` before Unity APIs. Independent ops: `UniTask.WhenAll`. (tech-stack §UniTask)
- State: private `ReactiveProperty<T>`, public `IReadOnlyReactiveProperty<T>`; events: private `Subject<T>`, public `IObservable<T>`; complete/dispose on owner dispose. (tech-stack §UniRx)
- Subscriptions: `.AddTo(this)` in `MonoBehaviour`; `CompositeDisposable` in plain classes; per-bind `CompositeDisposable` cleared in `Unbind()` for rebindable views. (tech-stack §UniRx)
- Button clicks: `OnClickAsObservable().ThrottleFirst(300ms)`. No `Observable.EveryUpdate`/`ObserveEveryValueChanged` in many objects; use `ITickable`. (tech-stack §UniRx)
- Tweens: `.SetLink` on destroyable targets; kill the previous tween before a new one; kill on disable/unbind/pool return; `.SetUpdate(true)` for paused UI. (tech-stack §DOTween)
- Await tweens with `ToUniTask(TweenCancelBehaviour.Kill, ct)`; combine with `DOTween.Sequence()`; never create tweens in `Update`. (tech-stack §DOTween)
- UI tweens via `VisualElementTweens` with `.SetId(this)`; prefer translate/scale/rotate/opacity over layout properties. (tech-stack §DOTween)
- Load assets only through injected `IAssetProvider`; reference by `AssetReference*`, not string paths; every load has a matching release. (tech-stack §Addressables)
- Asset in an Addressables group must not be referenced directly from scenes/non-addressable assets. (tech-stack §Addressables)
- UI: MVVM with plain C# ViewModels/Views (`ElementView` → `View<T>` → `WindowView<T>`); no `MonoBehaviour` per view. (tech-stack §UI Toolkit)
- Windows open via `IUIService`; layouts are `VisualTreeAsset`s loaded via `IAssetProvider`. Never build scenes/UI from editor scripts. (tech-stack §UI Toolkit)
- Sometimes-shown elements: create on first show, remove from hierarchy when hidden. Query by name once in `OnAttached`. Pool repeats with `ElementPool<T>`. Non-clickable: `picking-mode="Ignore"`. (tech-stack §UI Toolkit)
- Game flow: `GameStateMachine` singleton, states are plain classes with `Enter(ct)`/`Exit(ct)`, started from an entry point. (tech-stack §Game Flow)
- Not in this digest, open tech-stack for: Addressables groups, scene loading, remote content, init (§Addressables); DOTween init and replayed tweens (§DOTween); UniTask Tracker, `WhenAny`, DOTween define (§UniTask); `CombineLatest`, mixing UniRx with UniTask (§UniRx); safe area (§UI Toolkit).

## Code style

- C# 9 only: no file-scoped namespaces, global usings, record structs. (code-style intro)
- `PascalCase`: types, members, constants, enums, namespaces; `I` prefix for interfaces; `T`/`TName` for generics. (code-style §Naming)
- `_camelCase` for private/protected fields (incl. `[SerializeField] private`); `camelCase` for params/locals. (code-style §Naming)
- `bool` members start `Is/Has/Can/Should`; `UniTask` methods end `Async` (not Unity messages, state `Enter`/`Exit`). (code-style §Naming)
- Events: verb/past tense (`Died`); handlers `OnDied`. Reactive members named after the value (`Coins`). (code-style §Naming)
- One type per file, named after it; no nested types, no second type in a file (even a small enum/struct). (code-style §Files and Namespaces)
- Block-scoped namespace matching folders (`Game.Features.Shop`); `using`s outside it, `System` first, then alphabetical, none unused. (code-style §Files and Namespaces)
- 4 spaces, Allman braces, one statement per line, ~120 columns. (code-style §Formatting)
- Always braces on `if/else/for/foreach/while/do`, even guard clauses (three lines). (code-style §Formatting)
- Expression body only for a single expression. `var` only when the type is obvious; target-typed `new()` OK for fields. (code-style §Formatting)
- Extract 3+ lines of one responsibility, or a repeated 3+ line block, into a named private method. (code-style §Methods and Class Size)
- UI class over ~200 lines: split into child views/controllers/builders. (code-style §Methods and Class Size)
- Always explicit access modifier; order: access, `static`, `abstract/virtual/override/sealed`, `readonly`, `async`. (code-style §Modifiers and Declarations)
- `sealed` unless built for inheritance; `readonly` if assigned only in constructor/initializer. (code-style §Modifiers and Declarations)
- Inspector fields: `[SerializeField] private`, never public. Expose state via properties, no public mutable fields. (code-style §Modifiers and Declarations)
- No magic numbers: `const`/`static readonly`; designer-tunable values (rewards, prices, counts, timings) load from config, not code. `const` only for contract values (names, classes, keys, prototype-1:1). (code-style §Modifiers and Declarations)
- Member order: constants, static fields, instance fields, events, properties, constructors (+ `[Inject] Construct`), methods. (code-style §Member Ordering)
- Within a kind: public → internal → protected internal → protected → private protected → private. Private Unity messages first in the private methods, lifecycle order. Caller above callee; overloads together. (code-style §Member Ordering)
- Fields/properties by type category: class (incl. Unity objects, UI elements, UniRx types), then struct, then primitive/string/enum; `[SerializeField]` first, `readonly` before mutable. (code-style §Member Ordering)
- No `#region` or group comments. Editing a file: put new members in the right group, don't reorder the rest. (code-style §Member Ordering)
- `UnityEngine.Object` null checks: `== null`/implicit bool; never `?.`, `??`, `is null`. (code-style §Unity-specific)
- Pair every subscription with a dispose in the same class. Required components via `[SerializeField]`/`[RequireComponent]`. (code-style §Unity-specific)
- UI names: `private const string <Element>Name = "kebab-name";` and `<Meaning>Class = "..."`; no repeated literals. (code-style §Unity-specific)
- UXML: kebab-case `name` only on queried elements; USS classes BEM-like (`home-play__title`, `toast--warning`), shared `kit-`/`icon-`. (code-style §Unity-specific)
- USS: first line comment (what it styles, which mockup); px sizes; colors from `Game.uss` variables. Decoration: `picking-mode="Ignore"`. (code-style §Unity-specific)
- Comments in English; explain why, not what; `// TODO:` with reason; no commented-out code. (code-style §Comments)
- Every `public` member (and public interface members) gets `///` with `<summary>` (third person, present tense, period). (code-style §Public API documentation)
- Add `<param>`, `<typeparam>`, `<returns>`, `<exception cref>` (incl. `OperationCanceledException` for token methods), `<remarks>` for constraints; use `<see cref>`; `<inheritdoc/>` when behavior is unchanged. (code-style §Public API documentation)
- Comments give context (caller/when, why, preconditions, side effects, ownership); never restate name or signature ("Gets the health."). (code-style §Comment content: context, not the obvious)
- Unclear `[SerializeField]` gets `[Tooltip]`. Update XML docs in the same change as API changes. (code-style §Comments)

## Topic files

- `unity-project-structure-rules.md`: open when creating files/folders/features/asmdefs or starting a new project (baseline layout + `scaffold/scaffold.py` and `kit.py init` in the kit repository). Feature code in `Features/<Feature>/`, shared in `Services/<Capability>/` only once a second feature needs it; `Bootstrap` → `Flow` → `Features` → `Services`, never upward; non-code assets under `Content/` moved via the Editor. (structure §Where code goes, §Assembly definitions)
- `unity-testing-rules.md`: open when changing logic in `Features/`/`Services/` or configs, or fixing bugs. EditMode tests in the same change; bug fix = failing test first; inject time/random/IO behind interfaces; don't unit-test thin Views. (testing §What to test, §Making logic testable)
- `unity-architecture-rules.md`: open for new classes, patterns, pooling, refactors. YAGNI (no interface with one implementation), DRY (shared view code goes to base classes), pool anything spawned repeatedly. (architecture §YAGNI, §DRY, §Object Pooling)
- `unity-ui-mvvm-rules.md`: open for any UI work. View is thin, no game logic and no direct service calls; actions go through ViewModel methods; bind in `OnBind` with `.AddTo(Bindings)`; toggle USS classes instead of inline styles. (ui-mvvm §View, §ViewModel)
- `unity-save-system-rules.md`: open when saving/loading data. Separate DTO with safe defaults and stable string IDs; atomic write (tmp + backup); never overwrite a broken file, move it aside. (save-system §Data Model, §Reliable Writes)
- `unity-csharp-optimization-rules.md`: open for hot code, per-frame logic, perf fixes. No allocations or `new` in `Update`; no `Find*` in `Update`; cache components/hashes; set `Label.text` only on change. (optimization §C#: Allocations and the Garbage Collector, §Unity Scripts: Update, GetComponent, Caching)
